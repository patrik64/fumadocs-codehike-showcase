Code Hike annotations are written as **comments inside the code block**.
The comment is removed from the rendered output; only its effect remains.
Each annotation is implemented by a small `AnnotationHandler` in
`app/components/annotations/`.

## Mark

`!mark` highlights the next line, `!mark(1:2)` a range, and
`!mark[/regex/]` highlights inline matches. An optional query sets the
color.

```js
function lorem(ipsum, dolor = 1) {
  // !mark
  return dolor
}

function ipsum(lorem, dolor = 1) {
  // !mark(1:2) gold
  const sit = lorem == null ? 0 : lorem.sit
  dolor = sit - amet(dolor)
  // !mark[/sit/] pink
  return sit ? consectetur(lorem) : []
}
```

## Callout

`!callout[/regex/] message` draws a speech bubble pointing at the match:

```js
const lorem = ipsum(dolor, sit)
// !callout[/amet/] This is a callout
const [amet, consectetur] = [0, 0]
lorem.adipiscing((sed, elit) => {
  if (sed) {
    amet += elit
  }
})
```

## Diff

`!diff -` and `!diff +` render removed and added lines, GitHub-style:

```js
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  // !diff -
  dolor = ipsum - sit
  // !diff +
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}
```

## File name

The fence meta drives presentation too. Put a file name after the language
(`js index.js`) and it replaces the language label in the header:

```js index.js
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : 1
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}
```

`Code` takes the first word of the meta that contains a dot as the name, and
falls back to the language when there is none:

```tsx app/components/code.tsx
const flags = codeblock.meta.split(' ').filter(Boolean);
// !mark
const filename = flags.find((f) => f.includes('.'));

<span>{filename ?? langLabels[codeblock.lang] ?? codeblock.lang}</span>
```

The Code Hike docs print the whole meta string as the title. Picking out one
word instead leaves room for flags beside it, which is how the next section
turns on line numbers.

## Line numbers

Add `-n` to the meta and the `line-numbers` handler joins the block. It sits
next to a file name without getting in its way:

```py fizzbuzz.py -n
def fizzbuzz(n):
    for i in range(1, n + 1):
        if i % 15 == 0:
            print("FizzBuzz")
        elif i % 3 == 0:
            print("Fizz")
        elif i % 5 == 0:
            print("Buzz")
        else:
            print(i)
```

## Copy button

The icon at the right of every header above is a copy button. It isn't an
annotation, just a small button rendered next to `Pre`, but it knows about
them: it copies `codeblock.code`, the code after Code Hike has lifted the
annotation comments out. Copy this block and paste it somewhere — the
`// !mark` behind the highlighted line doesn't come along:

```js
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  // !mark
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}
```

Trimmed of its styling, the button is this:

```tsx app/components/code.tsx
function CopyButton({ text }: { text: string }) {
  const [copied, setCopied] = useState(false);

  return (
    <button
      aria-label="Copy to clipboard"
      onClick={() => {
        navigator.clipboard.writeText(text);
        setCopied(true);
        setTimeout(() => setCopied(false), 1200);
      }}
    >
      {copied ? <Check size={14} /> : <Copy size={14} />}
    </button>
  );
}

// !callout[/codeblock.code/] already free of annotation comments
<CopyButton text={codeblock.code} />
```

## Composition

Handlers compose — one block can combine all of the above:

```ts checkout.ts -n
async function checkout(cart: Cart) {
  // !diff -
  const total = cart.items.reduce((sum, i) => sum + i.price, 0)
  // !diff +
  // !mark[/subtotal/]
  const subtotal = sum(cart.items.map((i) => i.price * i.quantity))
  // !callout[/tax/] Tax is computed server-side since v2
  const tax = await fetchTax(cart.address, subtotal)
  return subtotal + tax
}
```

## Code mentions

`!hover name` works the other way round: the comment only names a line, and
a link in the prose — `[base case](hover:one)` — points at it. Hover a
mention, or tab to it, and every other line of the block dims:

<HoverContainer>

The [base case](hover:one) returns 1 without calling anything.

```cpp
int factorial(int n) {
  if (n == 0) {
    // !hover one
    return 1;
  } else {
    // !hover two
    return n * factorial(n - 1);
  }
}
```

The [recursive case](hover:two) multiplies `n` by the factorial of `n - 1`.

</HoverContainer>

Three small pieces make this work: `<HoverContainer>` remembers which mention
is active, the `a` component in `app/components/mdx.tsx` turns `hover:` links
into mentions, and the `hover` handler dims the lines that weren't named.

## Token transitions

`tokenTransitions` is a handler like the others, but it isn't attached to a
line: it watches the whole block. When the code handed to `Pre` changes, the
tokens both versions share slide to their new positions and the new ones
fade in. Press the button to switch between two versions of one function:

<CodeSwitcher>

```scala !!versions
object Main {
  def factorial(n: Int): Int = {
    if (n == 0) {
      return 1
    } else {
      return n * factorial(n - 1)
    }
  }
}
```

```python !!versions
def factorial(n):
    if n == 0:
        return 1
    else:
        return n * factorial(n - 1)
```

</CodeSwitcher>

Each fence marked `!!versions` is one version of the code. Stripped of its
styling, the component is a `Pre` whose `code` prop changes on click:

```tsx app/components/code-switcher.tsx
const [index, setIndex] = useState(0);

return (
  <>
    <Pre code={versions[index]} handlers={[tokenTransitions]} />
    <button onClick={() => setIndex((index + 1) % versions.length)}>
      Switch code
    </button>
  </>
);
```

The handler does the rest. It renders `Pre` through a small class component
that records where every token sits just before React updates the block,
then animates each one from its old position to the new one with the Web
Animations API. That is why the update has to happen in place: if the `Pre`
is remounted, there is no "before" to animate from.

The layouts on the next pages — [Scrollycoding](/docs/scrollycoding),
[Spotlight](/docs/spotlight) and [Slideshow](/docs/slideshow) — hand the
same handler to their code panels.
