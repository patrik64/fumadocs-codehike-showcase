Code Hike annotations are written as **comments inside the code block**.
The comment is removed from the rendered output; only its effect remains.
Each annotation is implemented by a small `AnnotationHandler` in
`app/components/annotations/`.

## Mark

`!mark` highlights the next line, `!mark(1:2)` a range, and
`!mark[/regex/]` highlights inline matches. An optional query sets the
color.

```js
function lorem(ipsum, dolor = 1) {
  // !mark
  return dolor
}

function ipsum(lorem, dolor = 1) {
  // !mark(1:2) gold
  const sit = lorem == null ? 0 : lorem.sit
  dolor = sit - amet(dolor)
  // !mark[/sit/] pink
  return sit ? consectetur(lorem) : []
}
```

## Callout

`!callout[/regex/] message` draws a speech bubble pointing at the match:

```js
const lorem = ipsum(dolor, sit)
// !callout[/amet/] This is a callout
const [amet, consectetur] = [0, 0]
lorem.adipiscing((sed, elit) => {
  if (sed) {
    amet += elit
  }
})
```

## Diff

`!diff -` and `!diff +` render removed and added lines, GitHub-style:

```js
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  // !diff -
  dolor = ipsum - sit
  // !diff +
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}
```

## File name

The fence meta drives presentation too. Put a file name after the language
(`js index.js`) and it replaces the language label in the header:

```js index.js
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : 1
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}
```

`Code` takes the first word of the meta that contains a dot as the name, and
falls back to the language when there is none:

```tsx app/components/code.tsx
export function codeLabel(codeblock: HighlightedCode) {
  const flags = codeblock.meta.split(' ').filter(Boolean);
  // !mark
  const filename = flags.find((f) => f.includes('.'));

  return filename ?? langLabels[codeblock.lang] ?? codeblock.lang;
}
```

The Code Hike docs print the whole meta string as the title. Picking out one
word instead leaves room for flags beside it, which is how the next section
turns on line numbers.

## Line numbers

Add `-n` to the meta and the `line-numbers` handler joins the block. It sits
next to a file name without getting in its way:

```py fizzbuzz.py -n
def fizzbuzz(n):
    for i in range(1, n + 1):
        if i % 15 == 0:
            print("FizzBuzz")
        elif i % 3 == 0:
            print("Fizz")
        elif i % 5 == 0:
            print("Buzz")
        else:
            print(i)
```

## Copy button

The icon at the right of every header above is a copy button. It isn't an
annotation, just a small button rendered next to `Pre`, but it knows about
them: it copies `codeblock.code`, the code after Code Hike has lifted the
annotation comments out. Copy this block and paste it somewhere — the
`// !mark` behind the highlighted line doesn't come along:

```js
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  // !mark
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}
```

Trimmed of its styling, the button is this:

```tsx app/components/code.tsx
export function CopyButton({ text }: { text: string }) {
  const [copied, setCopied] = useState(false);

  return (
    <button
      aria-label="Copy to clipboard"
      onClick={() => {
        navigator.clipboard.writeText(text);
        setCopied(true);
        setTimeout(() => setCopied(false), 1200);
      }}
    >
      {copied ? <Check size={14} /> : <Copy size={14} />}
    </button>
  );
}

// !callout[/codeblock.code/] already free of annotation comments
<CopyButton text={codeblock.code} />
```

## Composition

Handlers compose — one block can combine all of the above:

```ts checkout.ts -n
async function checkout(cart: Cart) {
  // !diff -
  const total = cart.items.reduce((sum, i) => sum + i.price, 0)
  // !diff +
  // !mark[/subtotal/]
  const subtotal = sum(cart.items.map((i) => i.price * i.quantity))
  // !callout[/tax/] Tax is computed server-side since v2
  const tax = await fetchTax(cart.address, subtotal)
  return subtotal + tax
}
```

## Focus

`!focus` is `!mark` turned inside out: instead of lighting the lines it
covers, it dims every other line of the block.

```js
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  // !focus(1:2)
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}
```

It has a second job when a block is shorter than its code: scrolling the
focused lines into view. The two versions below are the same code with the
comment moved from `lorem` to `dolor`, inside the switcher that
[Token transitions](#token-transitions) explains. Press the button:

<CodeSwitcher label="Move focus">

```js !!versions
// !focus(1:5)
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}

function ipsum(ipsum, dolor = 1) {
  return dolor
}

function dolor(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}
```

```js !!versions
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}

function ipsum(ipsum, dolor = 1) {
  return dolor
}

// !focus(1:5)
function dolor(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}
```

</CodeSwitcher>

Two jobs, two parts. `Line` and `AnnotatedLine` do the dimming, and a custom
`Pre` measures the focused lines after every render and scrolls when one of
them is out of sight:

```tsx app/components/annotations/focus.tsx
export const focus: AnnotationHandler = {
  name: 'focus',
  onlyIfAnnotated: true,
  // !mark
  PreWithRef: PreWithFocus,
  Line: (props) => <InnerLine merge={props} className="opacity-50 data-[focus]:opacity-100" />,
  AnnotatedLine: (props) => (
    <div className="-mx-2 bg-fd-foreground/5 px-2">
      <InnerLine merge={props} data-focus={true} />
    </div>
  ),
};
```

## Fold

`!fold` hides part of a line behind an ellipsis until it is clicked. Given a
regex with the `gm` flags, one comment at the top of the block folds every
match, and a capture group narrows the fold to what is in the parentheses.
Here `// !fold[/className="(.*?)"/gm]` makes this site's own `Code` markup
readable again:

```tsx app/components/code.tsx
// !fold[/className="(.*?)"/gm]
<div className="not-prose my-6 overflow-hidden rounded-lg border bg-(--ch-16)">
  <div className="flex items-center gap-2 border-b bg-fd-secondary/50 px-3 py-1.5">
    <span className="flex-1 font-mono text-xs text-fd-muted-foreground">
      {codeLabel(codeblock)}
    </span>
    <CopyButton text={codeblock.code} />
  </div>
  <CodeBody codeblock={codeblock} />
</div>
```

Click any `...` to see what it hides. The fold is presentation only: the copy
button still copies the complete code.

The handler is an `Inline` component with one piece of state. This is the
real file, with its own class names folded by the same comment:

```tsx app/components/annotations/fold.tsx
// !fold[/className="(.*?)"/gm]
const InlineFold: AnnotationHandler['Inline'] = ({ children }) => {
  const [folded, setFolded] = useState(true);
  if (!folded) return children;

  return (
    <button
      type="button"
      aria-label="Expand"
      className="rounded bg-fd-muted px-1 text-fd-muted-foreground hover:bg-fd-accent hover:text-fd-accent-foreground"
      onClick={() => setFolded(false)}
    >
      ...
    </button>
  );
};

export const fold: AnnotationHandler = {
  name: 'fold',
  Inline: InlineFold,
};
```

## Footnotes

`!ref` attaches a note to a line without putting it in the code: the line
gets a number, and the notes are listed under the block.

```rb
# !ref Library import
require 'sinatra'

# !ref URL mapping
get '/hi' do
  "Hello World!"
end
```

This is the one annotation a handler can't finish alone, because something
has to count the notes and print the list. `CodeBody`, the part of `Code`
that renders the lines, does that: it calls `numberFootnotes` and puts a
`<Footnotes>` list under the `Pre`. The digits are drawn by CSS, so they stay
out of anything you select and copy.

```tsx app/components/annotations/footnotes.tsx
// !fold[/className="(.*?)"/gm]
export const footnotes: AnnotationHandler = {
  name: 'ref',
  AnnotatedLine: ({ annotation, ...props }) => (
    <div className="flex gap-2">
      <InnerLine merge={props} />
      <Marker n={annotation.data.n} />
    </div>
  ),
};

export function numberFootnotes(codeblock: HighlightedCode) {
  const notes: string[] = [];
  const annotations = codeblock.annotations.map((annotation) => {
    if (annotation.name !== 'ref') return annotation;
    notes.push(annotation.query);
    return { ...annotation, data: { ...annotation.data, n: notes.length } };
  });

  return { code: { ...codeblock, annotations }, notes };
}
```

## Tooltip

`!tooltip[/regex/] text` tucks a note behind a token. Hover the dashed word,
or click it:

```js
// !tooltip[/lorem/] A made-up library, here only for the example
import { read, write } from "lorem"
```

The note doesn't have to be plain text. Inside `<CodeWithTooltips>` the text
after the regex names a `## !!tooltips` section instead, and whatever MDX
that section holds becomes the tooltip, another code block included:

<CodeWithTooltips>

```js !code
// !tooltip[/lorem/] description
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  dolor = sit - amet(dolor)
  // !tooltip[/consectetur/] inspect
  return sit ? consectetur(ipsum) : []
}
```

## !!tooltips description

**Hello world**

Lorem ipsum **dolor** sit amet `consectetur`.

Adipiscing elit _sed_ do eiusmod.

## !!tooltips inspect

```js
function consectetur(ipsum) {
  const { a, b } = ipsum
  return a + b
}
```

</CodeWithTooltips>

`CodeWithTooltips` matches each annotation to a section by name and hands the
section's content to the handler as `data.children`. The popup is Fumadocs
UI's popover, where the Code Hike docs use shadcn's tooltip, so its content
can hold links and buttons and stays open while you use them.

```tsx app/components/annotations/tooltip.tsx
// !fold[/className="(.*?)"/gm]
export const tooltip: AnnotationHandler = {
  name: 'tooltip',
  Inline: ({ children, annotation }) => (
    <Popover>
      <PopoverTrigger
        openOnHover
        className="cursor-pointer underline decoration-dashed underline-offset-4"
      >
        {children}
      </PopoverTrigger>
      <PopoverContent
        align="start"
        className="flex w-fit max-w-[min(24rem,98vw)] flex-col gap-2 [&_p_code]:rounded [&_p_code]:bg-fd-muted [&_p_code]:px-1 [&_p_code]:font-mono [&_p_code]:text-[0.85em] [&>.not-prose]:my-0"
      >
        {annotation.data?.children ?? annotation.query}
      </PopoverContent>
    </Popover>
  ),
};
```

## Code mentions

`!hover name` works the other way round: the comment only names a line, and
a link in the prose — `[base case](hover:one)` — points at it. Hover a
mention, or tab to it, and every other line of the block dims:

<HoverContainer>

The [base case](hover:one) returns 1 without calling anything.

```cpp
int factorial(int n) {
  if (n == 0) {
    // !hover one
    return 1;
  } else {
    // !hover two
    return n * factorial(n - 1);
  }
}
```

The [recursive case](hover:two) multiplies `n` by the factorial of `n - 1`.

</HoverContainer>

Three small pieces make this work: `<HoverContainer>` remembers which mention
is active, the `a` component in `app/components/mdx.tsx` turns `hover:` links
into mentions, and the `hover` handler dims the lines that weren't named.

## Tabs

`<CodeWithTabs>` turns several fences into one block. Each fence marked
`!!tabs` becomes a tab, titled by its file name, and a tab can do whatever a
plain block can: annotations, line numbers, footnotes, and a copy button that
follows the tab you are on.

<CodeWithTabs>

```js !!tabs main.js
function lorem(ipsum, dolor = 1) {
  const sit = ipsum == null ? 0 : ipsum.sit
  // !mark
  dolor = sit - amet(dolor)
  return sit ? consectetur(ipsum) : []
}
```

```css !!tabs styles.css
body {
  margin: 0;
  padding: 0;
}
```

</CodeWithTabs>

Code Hike only collects the fences. The tabs are Fumadocs UI's, where the
Code Hike docs use shadcn's, and each panel renders the same `CodeBody` a
plain block does. It is the mirror image of the
[tabs on the Fumadocs UI page](/docs/fumadocs-ui#tabs), which put whole code
blocks inside Fumadocs' tabs.

```tsx app/components/code-tabs.tsx
// !fold[/className="(.*?)"/gm]
<Tabs
  value={active}
  onValueChange={setActive}
  className="not-prose my-6 overflow-hidden rounded-lg border bg-(--ch-16)"
>
  <div className="flex items-center gap-2 border-b bg-fd-secondary/50 px-3">
    <TabsList className="flex-1 px-0">
      {tabs.map((tab, i) => (
        <TabsTrigger key={i} value={String(i)} className="font-mono text-xs">
          {codeLabel(tab)}
        </TabsTrigger>
      ))}
    </TabsList>
    <CopyButton text={tabs[Number(active)].code} />
  </div>
  {tabs.map((tab, i) => (
    <TabsContent
      key={i}
      value={String(i)}
      className="rounded-none bg-transparent p-0 data-[ending-style]:hidden"
    >
      <CodeBody codeblock={tab} />
    </TabsContent>
  ))}
</Tabs>
```

## Token transitions

`tokenTransitions` is a handler like the others, but it isn't attached to a
line: it watches the whole block. When the code handed to `Pre` changes, the
tokens both versions share slide to their new positions and the new ones
fade in. Press the button to switch between two versions of one function:

<CodeSwitcher>

```scala !!versions
object Main {
  def factorial(n: Int): Int = {
    if (n == 0) {
      return 1
    } else {
      return n * factorial(n - 1)
    }
  }
}
```

```python !!versions
def factorial(n):
    if n == 0:
        return 1
    else:
        return n * factorial(n - 1)
```

</CodeSwitcher>

Each fence marked `!!versions` is one version of the code. Stripped of its
styling, the component is a `Pre` whose `code` prop changes on click:

```tsx app/components/code-switcher.tsx
const [index, setIndex] = useState(0);

return (
  <>
    <Pre code={versions[index]} handlers={[tokenTransitions]} />
    <button onClick={() => setIndex((index + 1) % versions.length)}>
      Switch code
    </button>
  </>
);
```

The handler does the rest. It renders `Pre` through a small class component
that records where every token sits just before React updates the block,
then animates each one from its old position to the new one with the Web
Animations API. That is why the update has to happen in place: if the `Pre`
is remounted, there is no "before" to animate from.

The layouts on the next pages — [Scrollycoding](/docs/scrollycoding),
[Spotlight](/docs/spotlight) and [Slideshow](/docs/slideshow) — hand the
same handler to their code panels.
