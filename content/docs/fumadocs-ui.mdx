Fumadocs is not only the frame around these pages. It ships a component
library meant to be used *inside* MDX, and every block below is one of those
components — registered once in `app/components/mdx.tsx` and then written as
plain tags in the Markdown.

Two things hold throughout: every code fence still renders through Code Hike,
and every component follows the light/dark toggle in the nav.

## Banner

`<Banner />` is the site-wide notice bar: a new release, a deprecation, a
conference. Two variants, `rainbow` and `normal`:

<Banner id="fumadocs-ui-banner-normal" variant="normal" changeLayout={false} className="relative my-6 rounded-lg">
  `variant="normal"` — a flat bar in the secondary colour.
</Banner>

Three things are worth knowing before you reach for it.

It is **sticky by design**: the component ships as `sticky top-0 z-40`, which
is what you want at the app root and not what you want inside an article,
where it rides over the content as you scroll. Both banners on this page pass
`className="relative"` to put them back in the flow.

It **reserves layout space** unless you say otherwise. `changeLayout` defaults
to `true`, which adjusts fumadocs' layout offsets to account for the bar —
correct at the root, wrong for a banner sitting inside a page, so both of
these pass `changeLayout={false}`.

It **stays dismissed**. Give it an `id` and the close button writes to
`localStorage`, so a reader who dismisses it does not see it again. That also
means it can vanish mid-demo if you dismissed it earlier — clear the entry
for `id` to bring it back.

```tsx app/root.tsx
// !callout[/id/] the close button remembers this id, so a dismissal sticks
<Banner id="release-2-0" variant="rainbow">
  Fumadocs 2.0 is out
</Banner>
```

At the root you would drop `changeLayout` entirely and let the layout make
room for the bar — the opposite of what both banners on this page do.

## Callouts

`<Callout />` comes from `fumadocs-ui/mdx` — no registration needed. It takes
a `type` of `info`, `warn`, `error`, `success` or `idea`, an optional `title`,
and an optional `icon` to override the default one.

<Callout type="info" title="Build-time highlighting">
  Code on these pages is highlighted while the site is built. No highlighter
  is shipped to the browser.
</Callout>

<Callout type="warn" title="Plugin order matters">
  `remarkCodeHike` has to run before fumadocs' remark plugins, or the
  `## !!steps` headings inside a `<Scrollycoding>` block leak into the table
  of contents.
</Callout>

<Callout type="idea">
  Callouts accept full MDX, including `inline code` and [links](/docs).
</Callout>

## Steps

`<Steps>` draws the vertical rail; each `<Step>` is one numbered item. Code
fences sit inside a step like anything else — and they are still Code Hike
blocks, so the rail and the highlighted code line up down the page.

<Steps>
  <Step>
    **Add the dependencies.** `codehike` alongside `fumadocs-core` and
    `fumadocs-mdx`.
  </Step>
  <Step>
    **Describe what Code Hike should do.** One config object, shared by the
    remark and recma plugins.

```ts vite.config.ts
const codeHikeConfig: CodeHikeConfig = {
  // !callout[/code/] every fence in every page renders through <Code />
  components: { code: 'Code' },
  // highlighted at build time; colors come from the --ch-* CSS variables
  syntaxHighlighting: { theme: 'github-from-css' },
};
```

  </Step>
  <Step>
    **Wire the plugins into the MDX pipeline.** In `vite.config.ts`, so the
    Node-only compiler plugins never reach the browser's module graph.
  </Step>
  <Step>
    **Write the component the fences render through.** This is the whole
    contract: a codeblock in, a `<Pre>` out.

```tsx app/components/code.tsx
export function Code({ codeblock }: { codeblock: HighlightedCode }) {
  return <Pre code={codeblock} handlers={[mark, diff, callout]} />;
}
```

  </Step>
  <Step>
    **Copy the annotation handlers you want.** Code Hike ships none — the
    files in `app/components/annotations/` started as copies from its docs,
    and each one is a React component keyed to a comment name.

```tsx app/components/annotations/mark.tsx
export const mark: AnnotationHandler = {
  name: 'mark',
  Line: ({ annotation, ...props }) => <InnerLine merge={props} />,
};
```

  </Step>
</Steps>

## Accordions

`<Accordions>` with an `<Accordion title="...">` per row. Give a row an `id`
and it gets a copyable deep link.

<Accordions>
  <Accordion title="Why is fumadocs-ui aliased to @fumadocs/base-ui?" id="base-ui">
    This project pins `"fumadocs-ui": "npm:@fumadocs/base-ui@16.14.5"`, the
    Base UI build of fumadocs UI. Imports read the same
    (`fumadocs-ui/components/tabs`), so the alias is invisible in page code.
  </Accordion>
  <Accordion title="Why isn't fumadocs' CodeBlock here?" id="codeblock">
    Because Code Hike owns the code fences on this site. `components.code`
    rewrites every fence into our `<Code />`, so fumadocs' own `CodeBlock`
    and `CodeBlockTabs` — which expect a `<pre>` child — never receive one.
    Pick one owner for code blocks; here it is Code Hike.
  </Accordion>
  <Accordion title="Why isn't GithubInfo here?" id="github-info">
    `<GithubInfo />` calls the GitHub API while rendering. Since every route
    in this app is prerendered, that call would run during `pnpm build` and
    an outage or a rate limit would break the build. It works — it just
    doesn't belong in a demo that has to build on demand.
  </Accordion>
</Accordions>

## Graph view

`<GraphView />` is the one component here you don't import — it arrives via
`npx @fumadocs/cli add graph-view`, which copies the source into your project.
Same bargain as Code Hike's annotation handlers: you own the file afterwards.

Every page is a node, every Markdown link between two pages is an edge, which
is why the docs collection in `app/lib/source.ts` sets
`extractLinkReferences: true` — that is what puts `extractedReferences` on each
page for `buildGraph()` to walk.

Drag a node, scroll to zoom, click one to go there.

## What this page is really showing

Fumadocs gives you the page and the furniture on it. Code Hike gives you the
code blocks, headless, and expects you to bring the components. The two meet
in `app/components/mdx.tsx`: one object, fumadocs' components and ours side by
side, and from there on it is all just Markdown.
