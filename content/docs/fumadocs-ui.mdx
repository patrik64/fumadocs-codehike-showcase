Fumadocs is not only the frame around these pages. It ships a component
library meant to be used *inside* MDX, and every block below is one of those
components — registered once in `app/components/mdx.tsx` and then written as
plain tags in the Markdown.

Two things hold throughout: every code fence still renders through Code Hike,
and every component follows the light/dark toggle in the nav.

## Cards

`<Cards>` and `<Card>` build the linked grid fumadocs uses for its own
"next steps" sections. An internal `href` is routed through React Router's

## Callouts

`<Callout />` comes from `fumadocs-ui/mdx` — no registration needed. It takes
a `type` of `info`, `warn`, `error`, `success` or `idea`, an optional `title`,
and an optional `icon` to override the default one.

<Callout type="info" title="Build-time highlighting">
  Code on these pages is highlighted while the site is built. No highlighter
  is shipped to the browser.
</Callout>

<Callout type="warn" title="Plugin order matters">
  `remarkCodeHike` has to run before fumadocs' remark plugins, or the
  `## !!steps` headings inside a `<Scrollycoding>` block leak into the table
  of contents.
</Callout>

<Callout type="idea">
  Callouts accept full MDX, including `inline code` and [links](/docs).
</Callout>

## Steps

`<Steps>` draws the vertical rail; each `<Step>` is one numbered item. Useful
for setup instructions that need code between the prose.

<Steps>
  <Step>
    **Add the dependencies.** `codehike` alongside `fumadocs-core` and
    `fumadocs-mdx`.
  </Step>
  <Step>
    **Wire the plugins into the MDX pipeline.** In `vite.config.ts`, so the
    Node-only compiler plugins never reach the browser's module graph.
  </Step>
  <Step>
    **Point `components.code` at your own component.** Every code fence in
    every page then renders through it.
  </Step>
  <Step>
    **Copy the annotation handlers you want.** Code Hike ships none — the
    files in `app/components/annotations/` started as copies from its docs.
  </Step>
</Steps>

## Accordions

`<Accordions>` with an `<Accordion title="...">` per row. Give a row an `id`
and it gets a copyable deep link.

<Accordions>
  <Accordion title="Why is fumadocs-ui aliased to @fumadocs/base-ui?" id="base-ui">
    This project pins `"fumadocs-ui": "npm:@fumadocs/base-ui@16.14.5"`, the
    Base UI build of fumadocs UI. Imports read the same
    (`fumadocs-ui/components/tabs`), so the alias is invisible in page code.
  </Accordion>
  <Accordion title="Why isn't fumadocs' CodeBlock here?" id="codeblock">
    Because Code Hike owns the code fences on this site. `components.code`
    rewrites every fence into our `<Code />`, so fumadocs' own `CodeBlock`
    and `CodeBlockTabs` — which expect a `<pre>` child — never receive one.
    Pick one owner for code blocks; here it is Code Hike.
  </Accordion>
  <Accordion title="Why isn't GithubInfo here?" id="github-info">
    `<GithubInfo />` calls the GitHub API while rendering. Since every route
    in this app is prerendered, that call would run during `pnpm build` and
    an outage or a rate limit would break the build. It works — it just
    doesn't belong in a demo that has to build on demand.
  </Accordion>
</Accordions>

## What this page is really showing

Fumadocs gives you the page and the furniture on it. Code Hike gives you the
code blocks, headless, and expects you to bring the components. The two meet
in `app/components/mdx.tsx`: one object, fumadocs' components and ours side by
side, and from there on it is all just Markdown.
